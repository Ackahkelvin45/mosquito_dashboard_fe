Data API Reference v1

Read-only HTTP API for researchers and external consumers of mosquito surveillance data: sensor readings, mosquito detections, devices and clusters.

Contents Authentication Data scope Endpoints Parameters Pagination Sensor readings Mosquito events Devices Clusters Export Rate limits Errors Versioning

All requests use the base URL:

https://your-api-host

Authentication

Create an API key in the dashboard under API Access (any signed-in, approved account). The raw key (mk_…) is shown once at creation — store it securely; only a hash is kept server-side. Send it on every request in the X-API-Key header:

curl -H "X-API-Key: mk_your_key_here" \
  "https://your-api-host/api/v1/devices"
Keep your key out of shared notebooks, repositories and URLs. If a key leaks, revoke it in the dashboard — revocation takes effect on the next request.

Data scope

A key reads exactly the data its owner can see in the dashboard:

Owner roleKey's data scope
Super adminAll clusters
Cluster admin / userTheir cluster + public clusters

Scope is evaluated live per request — revoking the key, deactivating the owner, or changing their cluster takes effect immediately. Requesting a cluster_id outside your scope is not an error: it simply yields no rows.

Pagination

Cursor endpoints (sensor-readings, mosquito-events)

{ "items": [ … ], "next_cursor": "MjAyNi0wMy0wMVQwMDowNTowMHwxMg==" }

Pass next_cursor back as cursor= to fetch the next page; null means you have everything. Cursors are stable under concurrent inserts — you will never see a row twice or skip one while walking.

Page endpoints (devices, clusters)

{ "items": [ … ], "total": 42, "page": 1, "page_size": 100, "total_pages": 1 }

Sensor readings

GET/api/v1/sensor-readings

Columns: id, timestamp, device_uuid, device_name, region, community, cluster_id, external_temperature, internal_temperature, external_humidity, internal_humidity, external_pressure, internal_pressure, external_light, battery_voltage, trap_status.

A month of readings for two devices, temperature only, oldest first:

curl -H "X-API-Key: $KEY" \
  "https://your-api-host/api/v1/sensor-readings?device_uuid=AI4PEP_1&device_uuid=AI4PEP_2&start_date=2026-06-01T00:00:00&end_date=2026-07-01T00:00:00&fields=timestamp,device_uuid,external_temperature&order=asc&limit=500"

Example response:

{
  "items": [
    {
      "timestamp": "2026-06-01T00:04:12Z",
      "device_uuid": "AI4PEP_1",
      "external_temperature": 29.4
    }
  ],
  "next_cursor": "MjAyNi0wNi0wMVQwMDowNDoxMnw4MTM2"
}

Mosquito events

GET/api/v1/mosquito-events

One flat row per detection event, joined with its species detail. Columns: id, timestamp, device_uuid, device_name, region, community, cluster_id, count, detection_timestamp, species, genus, age_group, sex.

Female Aedes detections:

curl -H "X-API-Key: $KEY" \
  "https://your-api-host/api/v1/mosquito-events?genus=aedes&sex=F"

Devices

GET/api/v1/devices

Columns: id, device_uuid, name, description, region, community, longitude, latitude, cluster_id, total_mosquito_count, last_activity, created_at. Supports search, sort and order.

Clusters

GET/api/v1/clusters

Columns: id, cluster_uuid, name, description, public, created_at.

Export

GET/api/v1/export
ParameterValues
datasetsensor-readings | mosquito-events | devices (required)
formatcsv (default) | jsonl — one JSON object per line

Accepts the same filters as the matching list endpoint; fields= trims columns. Rows stream oldest-first and the response is chunked, so arbitrarily large date ranges download in constant memory. CSV columns are in the fixed order listed per dataset above; empty cells are NULLs; text cells beginning with = + - @ are prefixed with ' to disarm spreadsheet formula injection.

A full year of events as CSV:

curl -H "X-API-Key: $KEY" -o events_2026.csv \
  "https://your-api-host/api/v1/export?dataset=mosquito-events&format=csv&start_date=2026-01-01T00:00:00&end_date=2027-01-01T00:00:00"

Python, walking every page of the list endpoint instead:

import requests

BASE = "https://your-api-host"
KEY  = "mk_..."

rows, cursor = [], None
while True:
    params = {"limit": 500, "order": "asc"}
    if cursor:
        params["cursor"] = cursor
    r = requests.get(f"{BASE}/api/v1/sensor-readings", params=params,
                     headers={"X-API-Key": KEY})
    r.raise_for_status()
    body = r.json()
    rows += body["items"]
    cursor = body["next_cursor"]
    if cursor is None:
        break

Rate limits

Limits are per account (the owner of the key — additional keys don't add budget):

BucketLimit
Query endpoints120 requests/min
Export5 exports/min, max 2 running at once

Exceeding a limit returns 429 with a Retry-After header (seconds).

Errors

Errors are JSON: { "detail": "message" }.

StatusMeaning
401Missing/invalid/revoked/expired key, or owner no longer active/approved
404Unknown route
422Invalid parameter (bad date, unknown fields/sort value, bad cursor, limit > 500)
429Rate limit or concurrent-export cap hit (see Retry-After)

Versioning

The API is versioned in the path (/api/v1/…). Backwards-incompatible changes will ship as /api/v2 with a deprecation window for v1. Additive changes (new optional parameters, new response fields) may occur within v1 — parse leniently.
